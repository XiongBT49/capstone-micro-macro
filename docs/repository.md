# 公开范围与完整本地资源

用户选择保留GitHub仓库为Public，并排除授权或公开范围尚未确认的内容。本地完整资料保留，Git只提交公开代码、通用角色配置、研究设计、汇总说明及三组合成测试。

## 不公开提交

| 本地目录 | 排除原因 |
|---|---|
| `vendor/gba/` | 第三方宏观包未授予开源许可，再分发受协作约定约束；包含数据库 |
| `zwtnew/` | 第三方动作与契约规范资源，公开范围尚未确认 |
| `data/`（说明页除外） | 原始企业、项目、关系及匹配数据尚未完成公开范围核对 |
| `Capstone报告/`、`output/`、`validation/` | 原始回答、输入、评分、实验数据库及来源材料 |
| `reports/` | 汇报材料和HKU模板，包含未确认公开范围的内容 |
| `research/references/`、`research/thesis_template/`、`research/admin/` | 原始研究附件、课程资料和模板 |
| `config/`（通用角色配置除外） | 场景、编译映射和真实输入配置暂保留本地 |
| `provenance/`、依赖原始材料的测试 | 迁移路径、历史记录、原始评审摘录及依赖资料 |

`.env`、虚拟环境、缓存、`runs/` 和 `.migration/` 同样忽略。`results/index.json` 只含汇总说明及本地相对路径，原始证据不随索引上传。

## 后续维护

日常开发继续使用当前完整本地目录。新增公开代码可正常提交；未公开资料继续保留本地，当前 `.gitignore` 默认排除这些目录。不能使用 `git add -f` 绕过公开边界。

后续如需公开数据或第三方包，应单独确认授权、数据处理与发布范围，再明确调整排除规则。新研究结果在本地 `results/experiments/<实验标识>/` 冻结并更新索引，经核对后另行选择可公开部分。

当前公开提交不包含大体积数据，不需要下载Git LFS对象；本地仍安装Git LFS，未来获准发布大文件时再配置具体规则。Git关闭自动换行转换，以保留源码字节。
