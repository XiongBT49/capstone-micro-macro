# 澳门新葡京酒店采购仿真对照

CASE-0206 · Capstone 组会 · 2026 年 11 月 19 日

**在这个案例中，多 agent 组的模拟结算额比单 agent 组低 669.36 万澳门元（4.08%）。** 两组都签下 6 个采购包，在第 42 个宏观时间步完成结算，均延误 7 天。多 agent 组的综合质量得分略低，模型调用次数约为单 agent 组的 8.67 倍。

## 我们想验证什么

当企业的采购决策由一个 agent 作出，或由多个 agent 分工协商时，中标企业和签约金额会怎样变化？这些变化能否在项目最终账目中找到对应记录？

我们选取澳门新葡京酒店的项目资料，构建了一个设计、招标、施工依次进行的采购情景（DBB）。两组使用相同的初始输入、1.5 亿澳门元情景预算、同一 DeepSeek 模型（`deepseek-flash`）、同一宏观规则和随机种子 42，各运行一次。业主在运行中自行拆包，所以两组最终的施工包范围和预算分配可以不同。以下金额均为仿真结果。

## 两组跑出了什么结果

| 指标 | 单 agent | 多 agent | 多 agent 相对单 agent |
|---|---:|---:|---:|
| 已签约采购包 | 6 / 6 | 6 / 6 | 相同 |
| 施工合同合计（万澳门元） | 12,335.50 | 11,750.00 | 少 585.50 万 |
| 项目最终结算（万澳门元） | 16,416.82 | 15,747.46 | 少 669.36 万（4.08%） |
| 结算超出情景总预算 | 9.45% | 4.98% | 少 4.46 个百分点¹ |
| 延误天数 | 7 | 7 | 相同 |
| 综合质量得分（宏观引擎） | 0.7824 | 0.7802 | 低 0.0022 |
| DeepSeek 调用次数 | 95 | 824 | 多 729 次 |
| API 估算费用（人民币） | ¥1.32 | ¥9.65 | 多约 ¥8.33 |

¹ 表内数值分别四舍五入，百分点差按未舍入的原值计算。API 费用按调用回执中的缓存命中、未命中和输出 token 分项估算。制作本报告直接读取已有文件。

## 从一份施工合同追到最终结算

1. **微观签约。** 多 agent 组将主体结构与土建工程包授予中交第一航务工程局有限公司，合同价为 **6,450 万澳门元**。第二个施工包涵盖机电安装与酒店专项系统，由中建八局第二建设有限公司以 **5,300 万澳门元**签下。单 agent 组划分了不同的施工范围，中建八局第二建设有限公司取得两个施工包。
2. **宏观登记。** 两个多 agent 施工包在采购会话里记录的企业成员和金额，都与宏观签约事件一致。宏观登记的施工合同总额正好是 **6,450 + 5,300 = 11,750 万澳门元**。两个材料包已包含在对应施工合同内，汇总时只计一次。
3. **项目结算。** 宏观引擎继续推进施工、付款和验收。第 42 个时间步的结算事件同时保留了 **11,750 万澳门元施工合同总额**和 **15,747.46 万澳门元最终结算额**。这两个字段让我们可以区分采购阶段形成的合同价格与项目完工后的总账。

## 对 Capstone 意味着什么

- **系统衔接得到了一次端到端验证。** 两组各有 6 份微观合同可以逐份核对到宏观签约事件，且各有一次最终结算。下一位组员可以从采购包查到中标人，再查到项目账目。
- **这个案例体现了成本与调用开销的取舍。** 多 agent 组结算额较低，工期相同，质量分略低，而且使用了更多模型调用。两组连拆包方案都不同，所以 4.08% 反映整套流程在本例的一次差异。跨案例、跨随机种子的平均提升仍待验证。
- **历史企业验证要先检查候选覆盖。** 数据库记录的施工企业是中国港湾工程有限责任公司（`COMP-0063`）。两组施工包的 3 家候选企业都没有它，因此两组都无法选中这家历史企业。全量微观实验的“从 24 家中选前三是否命中”是另一个研究指标，需要用该实验自己的样本和分母报告。

## 怎样复核

运行目录为 `runs/selected-six-20261119/CASE-0206/`。初始情景在 `initial.json`，两组结果分别在 `single/`、`multi/`。各组的 `shared_input.json` 记录拆包与候选，`sessions/` 记录投标和签约，`result.json` 记录宏观事件。查找 `package_contract_committed` 可复核企业与金额，查找 `final_account_settled` 可复核最终结算。单组结算事件编号为 `EVT000637`，多组为 `EVT000634`。
