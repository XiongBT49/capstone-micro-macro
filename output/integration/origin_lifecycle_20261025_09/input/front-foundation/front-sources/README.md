# 融资与专业委任的同一运行装配

运行 `& ./run.ps1`，已有输出时指定新的 OutputDirectory。此输入包尚待集中业务联调。
同一个原生引擎、组织/授权快照、动作登记器、任务库和业务时钟，覆盖八角色。
--professional-project-object-types 接受包含 PGEN0001/PGEN0002 的 JSON 对象，在封装前声明两个专业来源的对象类型；原服务条款、能力与方法支持域由已有生成器一起生成，运行期仍要求与实际项目匹配。它不推断真实资质，也不在来源不匹配时改写原资料。
一个业主、两个银行、两名建筑师及其余支持角色均预先明确提供；宏观产生实际项目。
--bank-actor-ids 接受原两家银行组织到执行 actor 的初始 JSON 映射。银行业务复用原授权表，其他初始来源仅同步没有授权、没有业务 actor 载荷的银行支持身份；已有授权或已绑定来源不改写。其他角色的执行身份沿用各自既有来源，不能用此参数迁移旧任务或代签。
融资复用原 Bank A01—A05 与 OWN-A05，专业委任复用三专业 A02/A03 与 OWN-A04。
微观动作仅在实际请求/本机构事件到达时执行；两类确认分别消费自己的实际选中事件。
后续业务仅读取严格较早的本机构真实反馈。专业费率、财务和物理容量仍是明确合成假设。
月度操作保留显式宏观原生路由；机会判断默认使用宏观原实现，可显式启用原 OWN-A03。未接管的后续业务不计入微观完成。
原生正式状态继续由宏观维护，不创建详细贷款、放款、服务付款或独立资源预留账本。
sources/bank/ 只提供初始资料，业务统一从顶层 run.ps1 启动。
sources/ 保留初始输入，顶层输入固定共享身份和时钟；历史输入和失败记录不改写。
监管、供应的主体、函数与时钟在生成材料及其内容/方法/协议/草稿摘要前绑定，不对已封装的来源做字符串换名。

initial-owner-funding.json 是立项、融资及借款人资料共用的初始合成现金/旧债声明；不是运行期资金账本。initial-owner-investment-preference.json 从原专业服务声明的共同地域形成显式场景立项偏好，由原 OWN-A03 拒绝不符合条件的机会；不扩大专业资质，也不限制其他输入场景支持的地域。专业委任资料按原生融资后下一时点发出委任的时序提供。

--max-prior-final-accounts N 需 --with-owner-opportunity：在后续真实立项机会中读取本业主严格较早的实际原生汇总结算事件，达到独立声明的次数阈值后由原 OWN-A03 暂缓新增投资。正式项目仍由宏观决定；不生成结算项目、不自动运行私有复核、不把汇总结算当作到账、清债、缺陷关闭或移交完成。三时点组合已有定向业务证据，其他配置与全量回归仍待集中核验。

已显式启用 --with-owner-opportunity：原 OWN-A03 复用同一授权运行时、登记器、任务库和锁处理真实立项机会，再由原宏观选择候选并创建项目。独立合成的财务、旧债、管理容量、资质和权利保持显式来源；不从能力分推现金，也不声称执行 OWN-A02/A16。--max-prior-initiations 和 --max-prior-payment-requests 可配置原私有偏好，均默认不限制；无本项开关时不接管立项。实际创建及可选付款请求历史仅供本业主后续使用，不创建正式资金或资源账本。

已显式启用 --with-owner-observation：当前机会请求先执行原 OWN-A01，再将真实 follow 结果、原来源与审计摘要交原 OWN-A03 读取。--owner-observation-minimum-demand 声明私有筛选阈值，默认 0；原 ignore 直接返回原宏观 defer_project，不执行 A03。观察使用当前原宏观全局需求指数，不冒充地区调查或专业预测；独立管理池、筛选工作量和研究许可均为场景声明。候选跟踪不创建正式项目、案件、权利或资源承诺；其他结果保留并停止复核。

已启用 --with-professional-opportunity：三个专业方在实际委任请求内执行原 A01，已形成的 express_interest 及当前请求证据交原 A02 消费；共用原授权、登记器和任务库。表达兴趣不等于接受、报价发布、收费或正式委任；其他 A01 结果保留并停止本次接单评估。

已启用 --with-professional-feedback：共享宿主复用原事件观察器及三专业 A12，分别记录实际接单接受/拒绝和原宏观团队中选结果；核对本机构原 A02、原提案/最终决定及真实收件。后轮原 A02 可读取自身已完成的中选记录，继续按既有次数策略接单；接受意向仍不等于中选。未中选计划保持未触发，已声明但缺失的历史反馈不自动重跑。记录不创建详细委任、收费、能力提升或训练。新增中选消费在独立真实业务中通过，共享组合留集中联调。

--with-owner-proposal 需同时启用 --with-owner-observation 与 --with-owner-opportunity：当前 A01 跟踪后，原 A16 实算有限草案与审阅预算/工作量，完整草案由原 A03 消费，非建设比较基线保留。原 no_proposal 不立即立项，部分草案保持待补；当前权利、规模支持域和审阅成本为明确合成初始假设，未执行 OWN-A02、专业报告、权利取得或支出。
