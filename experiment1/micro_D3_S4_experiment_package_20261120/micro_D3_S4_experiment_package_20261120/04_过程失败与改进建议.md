# 微观D3、S4实验：过程失败与改进建议

本文件为按要求删减后的展示副本；完整原始实验保存在资料包之外。其余质量评分、过程失败和费用未因本次删减而调整。

本文件把已经观察到的过程问题、已经实施的优化、未来尚未实施的建议分开。所有原始失败和费用均保留，本次整理没有新增模型请求或改变评分。

## 2. 无效步骤的首个校验错误

|首个错误类型|S4|D3|G3（辅助）|
|---|---:|---:|---:|
|e最多3条|51|154|23|
|引用未提供或不存在的证据ID|35|49|3|
|r须为1至12完整排列|2|11|1|
|已知计费业务输出未完成或格式无效|1|9|2|
|候选依据引用其他候选或项目/任务ID|0|4|1|
|风险条目须恰有q/c|0|1|1|

这是每个无效步骤首先触发的校验错误，不是对一份响应全部问题的穷举；同一份文本可能还有其他问题。13次供应商层已知计费业务响应失败中，生成阶段12次、评价阶段1次；不能把这13次与全部结构无效步骤数直接相加。
D3最主要问题为依据e超过3项（154次）和引用未提供/不存在的证据ID（49次）。超过条数首先是输出契约失败，不必然表示这条业务意见语义错误；引用合法也不代表业务判断已经被人工核验。
## 3. 历史排序仍是强参照

S4最终Top1相对历史第一名改变18/433条（4.16%），D3改变20/433条（4.62%）。

当前只能观察到保守排序，不能单独识别其原因。历史统计有效、输入资料稀疏、原排名提示和缺乏可核验的岗位冲突都可能有关，本轮没有分别随机化这些因素。固定12家候选的覆盖上限也限制了重排序可获得的空间。
## 4. 评分缺失与顺序影响

原严格理由上限40字符导致较多解析失败，测试只有169/295完整配对。预先声明的最大长度160字符敏感性分析只恢复长度单一原因；保留原评分、全文理由、引用和全部原失败状态，业务响应失败不恢复。主比较共恢复199个顺序，G3比较恢复29个顺序；剩余原业务失败仍保持失败。
敏感性分析支持约1.41%的自动代理分优势，仍未达到8%。不能把辅助口径悄悄换成主口径，也不能因为合法配对多了就把差异归于模型方案变化。
同一模型同时生成和评价，存在共同偏好。双顺序匿名可以检查位置影响；它不是人工专家盲评。导出的人工评分表保持空白，尚未实际完成专家评估。
## 5. 为什么尚不能归因于岗位专业分工

S4与D3同时改变了“串行自检”及“独立三意见汇总”的结构和岗位提示。G3消融把汇总结构保持一致，仅改变前三步是否分技术、商务、交付岗位。D3相对G3的差值在严格口径约−0.25%、敏感性口径约−0.27%，区间均跨0；本轮未发现岗位分工的显著净收益。

## 6. 本轮已经实施的优化

|实际已实施|目的与证据|
|---|---|
|直接复用冻结12候选|核对NPZ及原顺序，不重建候选后补回；433条候选与标签保持|
|已有事实无损整理|压缩展示、来源定位、值哈希、引用ID；输入事实修改0、外部事实新增0|

## 8. 过程指标阅读注意

intermediate_metrics.csv中的依据、风险、待核查项等数量也可能来自未通过整体校验的parsed内容，是原始输出的可观察数量；不能全算成有效岗位贡献。independent_intermediate_summary.json中的证据/风险统计只累计结构有效步骤。本包逐条分析应结合valid、status及error理解，二者分母与统计范围不同并非矛盾。
格式与引用校验通过不验证引用解释是否正确，不验证所有风险是否已覆盖。风险条数受每步最多2条的固定格式约束，不能把“条数更多”解释为“风险识别更准”。
本轮没有运行微观输出后的生命周期模拟，也没有现实项目成本、收入、回款观测，因此不存在本轮可验证的现实盈利增益。
